리액트 함수 넘기기 노트
React 기초 노트

함수를 넘긴다는 것과 렌더링 타이밍

onClick에 괄호를 붙이면 안 되는 이유, 그리고 setState에 함수를 넘기는 이유를 한 번에 정리했어요. 두 이야기는 같은 뿌리에서 나와요. 함수는 값이고, React는 렌더링 단위로 움직인다는 점이에요.

Part 1

onClick에서 ()를 붙일 때와 안 붙일 때

괄호 ()가 붙으면 지금 당장 실행, 안 붙으면 함수 자체(나중에 실행할 것)예요.

함수는 값이에요

function hello() {
  console.log("안녕");
}

hello      // 함수 자체. 실행 안 됨
hello()    // 실행됨. 콘솔에 "안녕"

hello는 레시피 종이이고 hello()는 그 레시피로 실제 요리를 하는 거예요. 함수는 숫자나 문자열처럼 변수에 담거나 다른 곳에 전달할 수 있어요.

{ } 안은 렌더링 때 계산되는 JS 식이에요

JSX의 { }는 "여기부터 JS야"라는 표시예요. 안의 식은 화면이 그려질 때 한 번 계산돼요. React의 특별 규칙이 아니라 JS 규칙이라서, 괄호가 있으면 어디서든 그 자리에서 실행돼요.

<button onClick={handleClick()}>

// JS가 하는 일을 풀어 쓰면
const result = handleClick();  // 렌더링 중에 실행됨
<button onClick={result}>      // result가 undefined이면 onClick={undefined}

onClick은 이미 계산이 끝난 값을 받을 뿐이라, 앞 단계에서 실행되는 걸 막을 수 없어요. 클릭해도 아무 일이 안 일어나는 이유예요.

onClick이 원하는 건 "함수"예요

onClick은 "클릭되면 이 함수를 실행해줘" 하고 함수를 맡기는 칸이에요. 실행은 React가 클릭 시점에 하고, 이벤트 객체 같은 인자도 React가 넣어줘요.

const handleClick = (event) => {   // event는 React가 넣어주는 인자
  console.log(event.target);
};

<button onClick={handleClick}>

내가 정한 인자를 넘기고 싶으면 () =>로 감싸요

React는 id 같은 내 값을 모르니까, "클릭되면 handleClick(id)를 실행하는 새 함수"를 만들어서 넘겨요. 화살표 함수는 만들기만 하고 실행하지 않아요. 안에 있는 handleClick(id)는 클릭 때 화살표 함수가 호출되어야 실행돼요.

정상 
onClick={() => handleClick(id)}
버그 
onClick={handleClick(id)}

설명을 위해 풀어 쓰면 이래요. result와 wrapper는 이해를 돕는 임시 이름이고, 실제로 이런 변수가 생기는 건 아니에요.

const wrapper = () => handleClick(id);  // 함수를 만들기만 함. 실행 X
<button onClick={wrapper}>                // 클릭 때 wrapper 실행 → handleClick(id) 실행
코드렌더링 때클릭 때결과
onClick={handleClick}아무 일 없음handleClick(event) 실행정상
onClick={() => handleClick(id)}함수만 만들어짐handleClick(id) 실행정상
onClick={handleClick(id)}바로 실행됨undefined라 아무 일 없음버그

handleClick은 이렇게 정의해요

function ItemList({ items }) {
  const handleClick = (id) => {     // 매개변수 id를 받도록 정의
    console.log(`${id}번 클릭됨`);
  };

  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>
          <button onClick={() => handleClick(item.id)}>
            {item.name}
          </button>
        </li>
      ))}
    </ul>
  );
}

이름으로 넘기는 것(onClick={handleClick})과 그 자리에서 함수를 쓰는 것(onClick={() => { ... }})은 같은 동작이에요. 로직이 한 줄 정도면 인라인, 길어지거나 여러 곳에서 쓰면 이름을 붙여 따로 빼요.

HTML과 헷갈리는 이유

<!-- HTML: 따옴표 안의 "문자열"이라서 괄호를 써도 클릭 때 실행 -->
<button onclick="handleClick()">

{/* React: { } 안은 진짜 JS 식이라서 괄호를 쓰면 즉시 실행 */}
<button onClick={handleClick}>

HTML에서는 괄호를 붙이는 게 정상이라서 그 습관이 React에서도 나와요. 그리고 onClick={handleClick(id)} 안에서 setState가 호출되면, 렌더링 → 상태 변경 → 다시 렌더링이 반복되어 Too many re-renders 에러가 나요.

Part 2

setState에 함수를 넘기는 이유와 렌더링 타이밍

이전 값을 바탕으로 새 값을 계산할 때는 setCount(prev => prev + 1) 형태가 안전해요. count는 렌더링마다 고정되는 값이기 때문이에요.

처음 질문한 코드는 어떻게 되나요

// 원래 코드
onClick={() => {
  setIsErr(() => (num.length <= 13 ? true : false));
}}

// 단순화. 이전 값을 안 쓰고, 조건식 자체가 boolean이라 삼항도 불필요
onClick={() => setIsErr(num.length <= 13)}

바깥 () =>는 클릭 때까지 실행을 미루려는 것이고, 안쪽 () =>는 setState의 함수형 업데이트예요. 안쪽은 이전 상태를 쓰지 않으니 생략할 수 있어요.

같은 state를 연속으로 바꾸면 결과가 달라져요

결과 +1 
setCount(count + 1);
setCount(count + 1);
결과 +2 
setCount(prev => prev + 1);
setCount(prev => prev + 1);

한 번의 렌더링 안에서 count는 그 시점의 값으로 고정돼요. 위쪽은 두 줄 모두 0 + 1을 계산해서 1이 되고, 아래쪽은 React가 앞 단계의 결과를 prev로 이어서 넣어주기 때문에 2가 돼요.

값을 직접 넘길 때 0 + 1, 0 + 1 "내가 본 잔액 0원에 1원 더해서 1원으로 적어줘"를 두 번 말한 것이라 1원이 돼요.
함수를 넘길 때 0 → 1 → 2 "장부에 적힌 잔액에 1원 더해줘"를 두 번 말한 것이라 2원이 돼요.

함수를 따로 나눠도 같은 문제가 생겨요

const handleClick  = () => { setCount(count + 1); };
const handleClick2 = () => { setCount(count + 1); };
  • 한 번의 클릭에서 둘 다 호출하면 두 함수가 같은 렌더링의 count(0)를 보고 있어서 결과는 1이에요.
  • 버튼을 따로 눌렀다면 그 사이에 렌더링이 일어나 count가 1로 갱신되고, 결과는 정상적으로 2가 돼요.

함수가 몇 개로 나뉘었는지는 중요하지 않아요. 같은 렌더링에서 만들어진 함수들은 그 렌더링의 count를 공유해요.

결국 렌더링이 언제 일어나느냐가 관건이에요

렌더링 1: count = 0이때 함수들이 만들어지고, 모두 count를 0으로 기억해요.
클릭하면 핸들러 실행setCount는 값을 바로 바꾸지 않고 "다음 렌더링 때 이 값으로 바꿔줘"라고 예약만 해요.
핸들러가 끝나면 React가 예약을 한꺼번에 처리이걸 배칭이라고 불러요.
렌더링 2: count = 1함수들이 새로 만들어지고, 이번엔 count를 1로 기억해요.
const handleClick = () => {
  setCount(count + 1);
  console.log(count);   // 여전히 0. 아직 렌더링 전이라서
};

count는 렌더링마다 찍히는 사진이에요. 사진 한 장 안에서는 값이 안 변하고, setCount는 "다음 사진은 이렇게 찍어줘"라는 주문서예요.

상황추천
새 값이 이전 값과 무관해요. setIsErr(num.length <= 13)값을 그대로 넘겨요
이전 값으로 계산해요 (+1, 토글, 배열에 추가)함수형 prev => ...
한 핸들러에서 같은 state를 여러 번 바꿔요함수형
setTimeout이나 비동기 콜백 안에서 바꿔요함수형 (오래된 값을 볼 위험이 있어요)

최종 정리

  1. 인자가 필요 없으면 onClick={handleClick}로 써요.
  2. 인자가 필요하면 onClick={() => handleClick(id)}로 감싸요.
  3. onClick={handleClick(id)}처럼 호출 형태로 직접 쓰면 렌더링 때 실행돼요.
  4. 이 규칙은 onChange, onSubmit, setTimeout, map 등 함수를 받는 모든 자리에 똑같이 적용돼요.
  5. 이전 값으로 새 값을 계산할 때는 setState(prev => ...)를 써요.
