1. 한마디로, 펼치기

묶음 안에 든 값을 꺼내 낱개로 풀어놓는다고 생각하면 됩니다. 상자째 들고 있던 과일을 책상 위에 하나씩 꺼내놓는 것과 같아요.

const nums = [1, 2, 3];

console.log(nums);      // [1, 2, 3]   배열 하나
console.log(...nums);   // 1 2 3       낱개 값 세 개

두 번째 줄은 console.log(1, 2, 3)과 같습니다. 펼친 값은 그 자리에 직접 적은 것처럼 동작해요.

2. 배열 스프레드

복사

const a = [1, 2, 3];
const b = [...a];   // 새 배열. a와 별개

b.push(4);
console.log(a);   // [1, 2, 3]  그대로
console.log(b);   // [1, 2, 3, 4]

const b = a로 대입하면 같은 배열을 가리키게 돼서 b를 고치면 a도 바뀝니다. 스프레드는 새 배열을 만들어요.

합치기와 중간에 끼워 넣기

const front = ['A', 'B'];
const back  = ['E', 'F'];

[...front, ...back];            // ['A', 'B', 'E', 'F']
[...front, 'C', 'D', ...back];  // ['A', 'B', 'C', 'D', 'E', 'F']
['0', ...front];                // ['0', 'A', 'B']  맨 앞에 추가

3. 객체 스프레드

복사와 병합

const user = { name: '민지', age: 28 };

const copy = { ...user };                  // { name: '민지', age: 28 }
const next = { ...user, city: '서울' };      // { name: '민지', age: 28, city: '서울' }

같은 키가 겹치면 뒤에 오는 값이 이깁니다

왼쪽에서 오른쪽으로 차례로 채워 넣기 때문에, 같은 키가 또 나오면 나중 값이 앞의 값을 덮어써요. 질문하신 <HxButton {...button} buttonSize="..." />에서 buttonSize가 우선하는 이유도 이것입니다.

직접 눌러보기: 순서를 바꾸면 결과가 달라져요
base 
{
  label: '저장',
  variant: 'primary',
  buttonSize: 'small'
}
override 
{
  buttonSize: 'large'
}

4. 리액트에서 자주 쓰는 세 가지 자리

① props 한꺼번에 넘기기

const buttons = [
  { id: 1, label: '저장', variant: 'primary' },
  { id: 2, label: '취소', variant: 'secondary' },
];

{buttons.map(button => (
  <HxButton key={button.id} {...button} buttonSize="large" />
))}

객체의 속성 하나하나가 props가 됩니다. 위 코드는 id, label, variant도 함께 넘겨요.

② state 객체의 일부만 바꾸기

const [form, setForm] = useState({ name: '', email: '' });

const handleName = (e) => {
  setForm(prev => ({ ...prev, name: e.target.value }));
  // email은 그대로 두고 name만 새 값으로 덮어씀
};

③ state 배열 추가, 삭제, 수정

const [todos, setTodos] = useState([]);

// 추가
setTodos(prev => [...prev, { id: Date.now(), text: '장보기', done: false }]);

// 삭제
setTodos(prev => prev.filter(t => t.id !== targetId));

// 수정 (해당 항목만 새 객체로)
setTodos(prev => prev.map(t => t.id === targetId ? { ...t, done: true } : t));
왜 굳이 새로 만들까요?

리액트는 state의 참조(주소)가 바뀌었는지 보고 다시 렌더링할지 결정합니다. todos.push(...)처럼 기존 배열을 직접 고치면 주소가 같아서 화면이 갱신되지 않을 수 있어요. 스프레드로 새 배열이나 객체를 만들어 넘기는 것이 기본 습관입니다.

5. rest와 구분하기

점 세 개는 같은데 쓰이는 자리에 따라 반대 역할을 합니다. 펼쳐서 풀어놓으면 스프레드, 남은 것을 모아 담으면 rest예요.

// rest: 구조분해에서 "나머지"를 모음
const { buttonSize, ...rest } = props;
// buttonSize는 따로 꺼내고, 나머지 속성은 rest 객체에 담김

// rest: 함수 매개변수에서 인자를 모음
function sum(...args) { return args.reduce((a, b) => a + b, 0); }

// spread: 모아둔 것을 다시 펼침
<button {...rest} />
Math.max(...[3, 9, 4]);   // 9

컴포넌트에서 특정 props만 직접 쓰고 나머지는 내부 요소에 그대로 넘길 때 두 가지를 함께 씁니다.

function HxButton({ buttonSize, children, ...rest }) {
  return <button className={`btn btn-${buttonSize}`} {...rest}>{children}</button>;
}

6. 주의할 점

얕은 복사라서 중첩 객체는 같이 바뀝니다

const a = { name: '민지', address: { city: '서울' } };
const b = { ...a };

b.address.city = '부산';
console.log(a.address.city);   // '부산'  address 객체는 공유됨

// 중첩된 값을 바꿀 땐 그 단계까지 각각 펼친다
const c = { ...a, address: { ...a.address, city: '부산' } };

undefined도 덮어씁니다

{ ...{ size: 'large' }, size: undefined }   // { size: undefined }

뒤에 같은 키가 있으면 값이 undefined여도 앞의 값을 지웁니다. props 기본값이 의도치 않게 사라질 수 있어요.

props 스프레드를 쓸 때

객체에 들어 있는 모든 속성이 넘어갑니다. 예를 들어 <button {...data} />처럼 일반 DOM 요소에 쓰면 data 안의 낯선 키가 그대로 HTML 속성으로 전달되어 경고가 뜰 수 있어요. 어떤 props가 넘어가는지 한눈에 안 보이는 단점도 있으니, 컴포넌트가 받는 props가 정해져 있다면 필요한 것만 골라 넘기는 편이 읽기 좋습니다.

8. 연습 문제

답을 먼저 생각해 본 다음 펼쳐서 확인해 보세요.

Q1. 아래 결과는 무엇일까요? 
{ ...{ a: 1, b: 2 }, b: 3, c: 4 }

{ a: 1, b: 3, c: 4 }
b는 뒤에 적은 3이 앞의 2를 덮어씁니다.

Q2. 두 코드 중 button의 variant가 항상 'primary'가 되는 쪽은? 
(가) <HxButton {...button} variant="primary" />
(나) <HxButton variant="primary" {...button} />

(가)입니다. 뒤에 적은 variant="primary"가 button 안의 variant를 덮어써요. (나)는 button에 variant가 있으면 그 값이 이깁니다.

Q3. todos 배열에서 id가 2인 항목의 done만 true로 바꾸는 코드를 써보세요. 
setTodos(prev =>
  prev.map(t => t.id === 2 ? { ...t, done: true } : t)
);

바꿀 항목만 새 객체로 만들고, 나머지는 그대로 돌려줍니다. 배열은 map이 새로 만들어 줘요.
