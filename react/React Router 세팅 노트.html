라우터란

브라우저 주소(URL)를 보고 어떤 화면을 보여줄지 정해 주는 장치입니다. 페이지를 새로 받아오지 않고 화면만 바꾸기 때문에 SPA에서 여러 화면을 나눌 때 씁니다.

URL 입력/클릭→router 객체에서 일치하는 라우트 찾기→RootLayout의 Outlet 자리에 페이지 렌더링
v7 import 규칙 v7에서는 패키지가 react-router 하나입니다. createBrowserRouter, Link, Outlet, 각종 훅은 react-router에서, RouterProvider만 react-router/dom에서 가져옵니다. react-router-dom은 더 이상 쓰지 않아도 됩니다.

1설치

npm install react-router

설치 후 package.json의 react-router 버전이 7 이상인지 확인하세요. 예전에 react-router-dom을 설치했다면 제거합니다.

npm uninstall react-router-dom

2@ 별칭 설정

@/app/routes/router처럼 @로 시작하는 경로를 쓰려면 타입스크립트 설정과 Vite 설정 두 곳을 맞춰야 합니다. tsconfig는 에디터와 타입 체크용, Vite 설정은 실제 번들용입니다.

tsconfig.app.json (Vite 템플릿은 tsconfig.json에도 같은 paths를 넣어야 에디터가 인식합니다)
{
  "compilerOptions": {
    "paths": { "@/*": ["./src/*"] }
  }
}
vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { fileURLToPath, URL } from 'node:url';

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
  },
});

설정을 바꾼 뒤에는 개발 서버를 재시작하고, 에디터가 인식하지 못하면 TS 서버를 재시작하세요.

라우트 정의는 app/routes, 화면은 pages/슬라이스/ui, 바깥에 공개할 것은 슬라이스의 index.ts에 모읍니다. App.tsx는 얇게 유지합니다.

4RootLayout 만들기

모든 페이지에 공통으로 붙는 틀입니다. 자식 라우트가 그려질 자리에 <Outlet />을 꼭 넣어야 합니다.

src/app/layout/RootLayout.tsx
import { Outlet } from 'react-router';

export function RootLayout() {
  return (
    <div>
      <header>공통 헤더</header>
      <main>
        <Outlet /> {/* 자식 페이지가 여기에 렌더링됨 */}
      </main>
    </div>
  );
}

5페이지와 index.ts

페이지는 named export로 만들고, 슬라이스의 index.ts에서 그대로 다시 내보냅니다.

src/pages/style-guide/ui/StyleGuideHome.tsx
export const StyleGuideHome = () => {
  return <>HOME</>;
};
src/pages/style-guide/index.ts
export { StyleGuidePage } from './ui/StyleGuidePage';
export { StyleGuideHome } from './ui/StyleGuideHome';

export 방식 한눈에

컴포넌트 파일index.ts가져오는 쪽
export const Fooexport { Foo } from './ui/Foo'import { Foo } from '@/pages/foo'
export default Fooexport { default as Foo } from './ui/Foo'import { Foo } from '@/pages/foo'
export default Foo(없이 직접)import Foo from './ui/Foo'
자주 하는 실수 파일은 export default인데 index.ts에서 export { Foo } from으로 쓰면 has no exported member 오류가 납니다. default는 default as로 이름을 붙여 내보내야 합니다.

6router.tsx 작성

어떤 URL에 어떤 페이지를 보여줄지 적는 파일입니다. 페이지는 lazy로 불러 URL에 접근할 때 코드를 받아오게 합니다.

src/app/routes/router.tsx
/* eslint-disable react-refresh/only-export-components */
import { createBrowserRouter } from 'react-router';
import { lazy, Suspense } from 'react';
import { RootLayout } from '@/app/layout/RootLayout';

const StyleGuideHome = lazy(() =>
  import('@/pages/style-guide').then((m) => ({ default: m.StyleGuideHome }))
);
const StyleGuidePage = lazy(() =>
  import('@/pages/style-guide').then((m) => ({ default: m.StyleGuidePage }))
);

const withSuspense = (element: React.ReactNode) => (
  <Suspense fallback={<div>로딩중...</div>}>{element}</Suspense>
);

export const router = createBrowserRouter([
  {
    path: '/',
    element: <RootLayout />,
    children: [
      { index: true, element: withSuspense(<StyleGuideHome />) },        // /
      { path: 'style-guide', element: withSuspense(<StyleGuidePage />) }, // /style-guide
    ],
  },
]);
  • children의 path는 부모 기준 상대 경로입니다. 'style-guide'는 /style-guide가 됩니다.
  • index: true는 부모 경로(/)와 정확히 일치할 때 보여줄 페이지입니다.
  • lazy는 default export를 기대하므로, named export는 .then으로 { default: ... } 모양으로 감쌉니다.
  • 첫 줄 eslint 주석은 이 파일이 컴포넌트가 아닌 router 객체를 내보내서 붙인 것입니다.

7앱에 연결

src/App.tsx
import { RouterProvider } from 'react-router/dom';
import { router } from '@/app/routes/router';

function App() {
  return <RouterProvider router={router} />;
}

export default App;
src/main.tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App';

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>
);

개발 서버를 켜고 /와 /style-guide에 들어가 각각 화면이 나오면 기본 세팅은 끝입니다.

8라우트 추가하기

같은 슬라이스에 페이지 추가

  • ui/ColorGuidePage.tsx를 만들고 named export로 작성
  • index.ts에 export { ColorGuidePage } from './ui/ColorGuidePage'; 추가
  • router.tsx에 lazy 선언과 라우트 추가

URL 계층을 묶고 싶을 때 (중첩 라우트)

{
  path: 'style-guide',
  children: [
    { index: true, element: withSuspense(<StyleGuideHome />) },     // /style-guide
    { path: 'colors', element: withSuspense(<ColorGuidePage />) },  // /style-guide/colors
  ],
},

path: 'style-guide/colors'처럼 한 줄로 써도 URL은 같습니다. 하위 화면이 늘어나 공통 레이아웃이 필요해지면 중첩 구조가 편합니다.

FSD에서 슬라이스를 나눌 때

완전히 다른 페이지(home, login 등)는 pages/home처럼 새 슬라이스 폴더와 index.ts를 만듭니다. 같은 index.ts를 거치는 페이지들은 같은 청크로 묶여 함께 로드될 수 있기 때문에, 코드 스플리팅을 따로 하고 싶다면 슬라이스를 나누세요.

lazy 대안: 라우트의 lazy 속성

{
  path: 'style-guide',
  lazy: async () => {
    const m = await import('@/pages/style-guide');
    return { Component: m.StyleGuidePage };
  },
},

이 방식은 Suspense 래퍼 없이 라우터가 로딩을 처리합니다. 지금 쓰는 React.lazy 방식과 섞지 말고 한쪽으로 통일하세요.

9링크와 이동

라우트를 정의한다고 링크가 자동으로 생기지는 않습니다. 클릭으로 이동하려면 화면에 Link를 넣습니다. <a href>와 달리 페이지 전체를 새로고침하지 않습니다.

import { Link, NavLink, useNavigate } from 'react-router';

<Link to="/style-guide/colors">색상 가이드</Link>

{/* 현재 주소와 맞으면 isActive가 true */}
<NavLink
  to="/style-guide"
  className={({ isActive }) => (isActive ? 'nav active' : 'nav')}
>
  스타일 가이드
</NavLink>

// 코드로 이동
const navigate = useNavigate();
navigate('/style-guide');

접속하자마자 다른 경로로 보내려면 { index: true, element: <Navigate to="/style-guide" replace /> }처럼 Navigate를 씁니다. replace를 붙이면 뒤로 가기에서 리다이렉트 루프가 생기지 않습니다.

10404와 에러 화면

없는 주소로 들어왔을 때는 path: '*' 라우트가, 라우트 안에서 에러가 났을 때는 errorElement가 보여줍니다.

export const router = createBrowserRouter([
  {
    path: '/',
    element: <RootLayout />,
    errorElement: <div>문제가 발생했습니다.</div>,
    children: [
      { index: true, element: withSuspense(<StyleGuideHome />) },
      { path: '*', element: <div>페이지를 찾을 수 없습니다.</div> },
    ],
  },
]);
