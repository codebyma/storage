클로저, 함수가 들고 다니는 가방

클로저는 이름이 어려워서 더 헷갈립니다. 뜻은 짧습니다. 그리고 리액트에서 "왜 옛날 값이 나오지?" 하는 문제는 거의 전부 이 한 가지 개념으로 설명됩니다.

함수는 만들어지는 순간, 그때 눈에 보이던 바깥 변수들을 가방에 담아서 평생 들고 다닙니다. 이 "함수와 가방"을 합쳐서 클로저라고 부릅니다.
바깥 변수 보기 가방 챙기기 변수 자체가 들어 있다 리액트에서는 부딪히는 곳 헷갈릴 때

1먼저, 함수 안에서는 바깥 변수가 보입니다

클로저를 배우기 전에 알아야 할 것은 이것 하나입니다. 함수 안쪽에서는 바깥에 있는 변수를 읽을 수 있습니다.

const course = "리액트";

function printCourse() {
  console.log(course);   // 함수 안에서 바깥 변수를 읽는다
}

printCourse();           // "리액트"

이미 자연스럽게 쓰고 계신 규칙입니다. 클로저는 이 규칙이 "함수가 다른 곳으로 떠나도 유지된다"는 데서 출발합니다.

2함수는 태어날 때 가방을 챙깁니다

함수를 만드는 함수를 보겠습니다. 안쪽 함수가 태어나는 순간, 그 자리에서 보이던 변수 n이 가방에 담깁니다.

function makeCounter() {
  let n = 0;                // makeCounter 안에서만 보이는 변수
  return function () {      // 이 함수가 태어나며 n을 가방에 담는다
    n = n + 1;
    return n;
  };
}

const a = makeCounter();
const b = makeCounter();

a(); a(); a();              // 1, 2, 3
b();                        // 1  (b는 자기 가방을 따로 갖고 있다)

makeCounter 실행은 이미 끝났는데도 n은 사라지지 않았습니다. 안쪽 함수의 가방이 붙잡고 있기 때문입니다. a와 b는 각자 다른 시점에 태어났으니 가방도 따로입니다.

함수 a
a의 가방n = 3
함수 b
b의 가방n = 1

직접 확인해 보세요. 아래 카드는 위 코드와 같은 방식으로 진짜 클로저를 만들어 씁니다.

데모 1 · 카운터마다 가방이 따로 있습니다

각 카드의 "누르기"는 자기가 태어난 순간의 가방만 열어 봅니다. 한 카드를 눌러도 다른 카드의 n은 변하지 않습니다.

3가방에는 값이 아니라 변수 자체가 들어 있습니다

여기가 가장 중요한 부분입니다. 가방에는 "그때의 값을 복사한 것"이 아니라 그 변수 자체가 들어 있습니다. 같은 변수를 누가 바꾸면, 함수도 바뀐 값을 봅니다.

let count = 0;
const show = () => console.log(count);

count = 5;
show();   // 5  (가방 속 count는 바깥의 그 count와 같은 변수라서 최신 값이 보인다)

그렇다면 리액트에서는 왜 옛날 값이 나올까요? 이유는 다음 장에 있습니다.

4리액트는 렌더마다 새 변수를 만듭니다

1편에서 본 것처럼 컴포넌트는 함수이고, 렌더링은 그 함수를 다시 부르는 일입니다. 함수가 불릴 때마다 const [count, setCount] = useState(0)가 실행되어 count 변수가 새로 만들어집니다. 아래 코드는 이 상황을 가장 단순하게 줄인 것입니다.

function render(count) {              // 렌더링 = 이 함수를 부르는 일
  return () => console.log(count);    // 이 함수의 가방에는 "이번 호출의 count"가 들어간다
}

const handler0 = render(0);           // 첫 번째 렌더
const handler1 = render(1);           // 두 번째 렌더

handler0();   // 0  (첫 렌더의 count는 영원히 0)
handler1();   // 1

3장과 다른 점은 이것입니다. 3장에서는 변수 하나를 모두가 공유했습니다. 리액트에서는 렌더마다 변수가 따로 생기고, 그 변수는 const라서 아무도 바꾸지 못합니다. 그러니 옛날 렌더에서 태어난 함수는 옛날 변수를 들고 있고, 그 값은 영원히 그대로입니다.

데모 2 · 렌더마다 태어난 함수가 기억하는 값
현재 화면의 count = 0

렌더를 몇 번 더 한 뒤, 맨 위쪽(옛날 렌더)의 "함수 실행"을 눌러 보세요. 옛날 함수는 화면이 바뀐 줄 모르고 자기 가방 속 값을 말합니다.

5리액트에서 실제로 부딪히는 곳

아래 세 가지는 모두 같은 현상입니다. "나중에 실행되는 함수"가 "만들어진 렌더의 count"를 들고 있는 것입니다.

상황함수가 기억하는 값해결
setCount(count + 1)를 한 핸들러에서 여러 번이번 렌더의 countsetCount(c => c + 1)
클릭 뒤 setTimeout 안에서 count 읽기클릭한 렌더의 count이전 값으로 계산한다면 함수형 업데이트. 최신 값이 꼭 필요하면 useRef(다음 노트)
useEffect(..., [])의 타이머 안에서 count 읽기첫 렌더의 count함수형 업데이트, 또는 의존성에 count 적기

해결책이 항상 "최신 값을 받아 오는 길"을 만들어 주는 것임을 눈여겨보세요. 함수형 업데이트는 가방 속 값이 아니라 리액트가 건네주는 최신 값을 쓰는 방법입니다.

6헷갈릴 때 던지는 세 가지 질문

  • 이 함수는 몇 번째 렌더에서 만들어졌나요? 함수가 만들어진 렌더가 그 함수의 "나이"입니다.
  • 그 렌더의 count는 몇이었나요? 그것이 이 함수 가방 속에 평생 들어 있는 값입니다.
  • 이 함수가 나중에 실행되나요? 타이머, effect, 이벤트 핸들러는 모두 나중에 실행됩니다. 그때도 가방 속 값을 씁니다.

자주 나오는 의문

const인데 값이 어떻게 바뀌나요? 바뀌는 게 아닙니다. 새 렌더에서 같은 이름의 새 변수가 만들어질 뿐이고, 옛 변수는 옛 함수 가방에 그대로 남아 있습니다.

클로저는 피해야 하는 건가요? 아닙니다. 이벤트 핸들러에서 props와 state를 읽는 것도 전부 클로저 덕분입니다. 문제는 "나중에 실행되는 함수가 옛날 값을 볼 수 있다"는 점을 알고 쓰느냐입니다.

이 노트는 앞의 "렌더링과 useEffect" 노트와 이어집니다. 다음으로는 최신 값을 따로 들고 있는 도구인 useRef를 보면 좋습니다.
