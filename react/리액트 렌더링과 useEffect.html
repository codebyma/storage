리액트 렌더링과 useEffect
리액트 학습 노트

state는 바꿨는데 왜 옛날 값이 나올까?

버튼을 세 번 눌렀는데 숫자가 1만 올라가거나, useEffect 안에서 계속 처음 값이 나온 적이 있다면 이 노트가 답입니다. 원인은 하나이고, 한 문장으로 먼저 말씀드립니다.

렌더링은 컴포넌트 함수를 다시 부르는 일이고, 함수가 불릴 때마다 그 순간의 state 값이 사진처럼 고정됩니다. 이 문장만 이해하면 아래 내용은 전부 같은 이야기의 반복입니다.
렌더링이란 고정된 값과 클로저 useEffect 둘이 만나는 곳 한 장 요약

1렌더링은 함수를 다시 부르는 일

리액트 컴포넌트는 JSX를 돌려주는 평범한 함수입니다. state가 바뀌면 리액트는 이 함수를 처음부터 다시 호출하고, 새로 돌아온 JSX대로 화면을 고칩니다. 이 "다시 호출"을 렌더링이라고 부릅니다.

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      {count}번 눌렀어요
    </button>
  );
}

여기서 눈여겨볼 점은 count가 const라는 것입니다. 변수가 0에서 1로 바뀌는 게 아닙니다. 함수가 한 번 더 불리고, 그 호출 안에서 count가 새로 1로 만들어집니다. 세 번 누르면 함수는 네 번 불립니다.

첫 번째 렌더count = 0onClick → setCount(0 + 1)
두 번째 렌더count = 1onClick → setCount(1 + 1)
세 번째 렌더count = 2onClick → setCount(2 + 1)

렌더마다 자기만의 count가 있고, 그 렌더에서 만들어진 onClick도 자기 count만 압니다.

2고정된 값과 클로저

클로저는 어려운 말이지만 뜻은 간단합니다. 함수는 만들어진 순간 주변에 있던 변수를 기억합니다. onClick에 넣은 화살표 함수는 렌더 도중에 만들어지므로, 그 렌더의 count를 기억한 채로 남습니다.

같은 버튼을 세 번 부르면

function handleClick() {
  setCount(count + 1);   // count가 0이면 setCount(1)
  setCount(count + 1);   // 여전히 count는 0이라서 setCount(1)
  setCount(count + 1);   // 또 setCount(1)
}

한 번의 클릭 안에서는 count가 계속 0입니다. 같은 값 1을 세 번 예약했으니 결과는 1입니다. 아래에서 직접 눌러 보세요.

데모 1 · 렌더 규칙을 흉내 낸 시뮬레이션
count = 0
버튼을 눌러 보세요.

해결은 함수형 업데이트

setCount(c => c + 1)처럼 함수를 넘기면 "지금 렌더의 count"가 아니라 "예약된 직전 결과"를 받아서 계산합니다. 그래서 세 번이면 정말 3이 늘어납니다.

setCount(c => c + 1);   // 0 → 1
setCount(c => c + 1);   // 1 → 2
setCount(c => c + 1);   // 2 → 3

기준은 간단합니다. 이전 값을 바탕으로 새 값을 만들 때는 함수형으로 씁니다. 값을 통째로 바꾸는 setName("민지") 같은 경우는 그냥 써도 됩니다.

시간이 지난 뒤에도 같은 일이 생깁니다

타이머처럼 나중에 실행되는 함수도 만들어진 순간의 값을 기억합니다. 데모 2에서 "3초 뒤 알려주기"를 누른 직후 +1을 여러 번 눌러 보세요.

데모 2 · setTimeout이 기억하는 값
count = 0
+1을 몇 번 누른 뒤 "3초 뒤 알려주기"를 누르고, 바로 +1을 더 눌러 보세요.

시뮬레이션에서는 "지금 count"를 따로 읽어 보여주지만, 실제 리액트의 타이머 함수는 클릭 당시의 값밖에 알지 못합니다.

3useEffect는 렌더가 끝난 뒤의 할 일

렌더링 중에는 화면에 무엇을 그릴지 계산만 해야 합니다. 서버에서 데이터 가져오기, 타이머 걸기, 이벤트 등록, document.title 바꾸기처럼 컴포넌트 바깥 세상에 손을 대는 일은 렌더가 끝난 뒤에 해야 하고, 그 자리가 useEffect입니다.

useEffect(() => {
  document.title = `${count}번 눌렀어요`;
}, [count]);

의존성 배열이 실행 시점을 정합니다

적는 방법effect가 실행되는 때자주 쓰는 곳
배열 없음렌더가 끝날 때마다거의 쓰지 않습니다
[]처음 화면에 나타난 뒤 한 번첫 데이터 불러오기, 이벤트 등록
[a, b]처음 한 번, 그리고 a나 b가 바뀐 렌더 뒤검색어가 바뀌면 다시 요청하기

배열에는 effect 안에서 읽는 값(state, props)을 모두 적는 것이 규칙입니다. 이 규칙이 왜 있는지는 다음 장에서 나옵니다.

cleanup은 뒷정리입니다

effect가 함수를 돌려주면 그것이 cleanup입니다. 등록한 것을 해제하는 데 씁니다.

useEffect(() => {
  const onResize = () => console.log(window.innerWidth);
  window.addEventListener("resize", onResize);

  return () => window.removeEventListener("resize", onResize);
}, []);
처음 나타남effect 실행
의존성 값이 바뀜이전 effect의 cleanup 실행
이어서새 값으로 effect 다시 실행
화면에서 사라짐마지막 cleanup 실행

개발 모드의 StrictMode에서는 effect가 처음에 두 번 실행되는 것처럼 보입니다. cleanup이 제대로 짝을 이루는지 점검하는 동작이라 정상입니다.

4둘이 만나는 곳

effect 함수도 결국 렌더 중에 만들어진 함수입니다. 그래서 2장의 규칙이 그대로 적용됩니다. effect는 자신이 만들어진 렌더의 값을 기억합니다. 의존성 배열을 비워 두면 그 effect는 첫 렌더에서 한 번만 만들어지고, 안에 있는 count는 영원히 0입니다.

useEffect(() => {
  const id = setInterval(() => {
    setCount(count + 1);   // 이 count는 첫 렌더의 0
  }, 1000);
  return () => clearInterval(id);
}, []);                       // count를 적지 않았으니 effect는 다시 만들어지지 않음

화면의 숫자는 1에서 멈춥니다. 매초 setCount(0 + 1)만 반복하기 때문입니다. 고치는 방법은 두 가지입니다.

권장 함수형 업데이트로 바꾸기 
useEffect(() => {
  const id = setInterval(() => {
    setCount(c => c + 1);
  }, 1000);
  return () => clearInterval(id);
}, []);

effect 안에서 count를 읽지 않으니 의존성에 적을 것이 없고, 타이머도 한 번만 만들어집니다.

대안 의존성에 count 적기 
useEffect(() => {
  const id = setInterval(() => {
    setCount(count + 1);
  }, 1000);
  return () => clearInterval(id);
}, [count]);

count가 바뀔 때마다 cleanup으로 타이머를 지우고 새로 만듭니다. 동작은 맞지만 매초 타이머를 다시 거는 셈입니다.

이것이 "effect 안에서 읽는 값은 의존성에 적는다"는 규칙의 이유입니다. 적지 않으면 effect가 옛날 값을 붙들고 있게 됩니다.

5한 장 요약

  • 렌더링은 컴포넌트 함수를 다시 부르는 일입니다. state가 바뀌면 일어납니다.
  • 함수가 불릴 때마다 그 렌더의 state가 고정됩니다. 변수가 바뀌는 게 아닙니다.
  • 이벤트 함수, 타이머, effect는 만들어진 렌더의 값을 기억합니다. 이것이 클로저입니다.
  • 이전 값으로 새 값을 만들 때는 함수형 업데이트를 씁니다.
  • useEffect는 렌더 뒤에 하는 일이고, 읽는 값은 의존성 배열에 모두 적습니다. 등록한 것은 cleanup으로 해제합니다.

다음으로 이어 보기 좋은 주제는 useRef입니다. 렌더와 상관없이 최신 값을 들고 있어야 하는 경우에 쓰는 도구입니다.
